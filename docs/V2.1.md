# T-English V2.1

## Product scope
The application is renamed T-English while retaining the repository, website origin and existing `english-communication-ai:v1` learning key. The original 197 lessons and 985 examples are unchanged. Vocabulary remains 432 entries; exercise count remains 591.

Daily goals default to one lesson, five words and six exercises. Activities are unique IDs per local calendar date; retries do not inflate daily counts. Legacy completion dates and latest exercise/word timestamps contribute to the current day's initial view.

Topic tests select twelve different exercises, four per type, from a selected topic or the full curriculum. The test score uses each question's first response within that run, independently of lifetime exercise scores. A retry can improve practice accuracy but never replaces that run's first result. Only completed tests are saved as quiz records; partially answered questions still remain in practice progress.

Weak-point analytics aggregate questions with an incorrect attempt by their linked vocabulary entry and lesson structure. They distinguish historically incorrect questions from questions whose latest response is still incorrect, rather than inventing a historical number of mistakes.

Exercise reports are local feedback records. They can be exported as JSON for the user to share. The app never claims a report was sent and never transmits feedback automatically.

## Grading and content
Reviewed lexical variants include UK spelling and several contextual equivalents; selected declarative sentence-order tasks permit a grammatical fronted time phrase. Contractions and case/punctuation normalization remain supported. The list is intentionally bounded; the app does not evaluate every possible free-form answer. Multiple-choice distractors exclude visibly overlapping Vietnamese meaning segments. Existing scores retain their historical first response; new grading rules apply when the learner answers again.

## Additive progress schema
Optional `goals`, `activity`, `reports` and `quizzes` extend the V1/V2 payload. Their structures are validated before import, including dates, IDs, text lengths and score consistency. Older backups default the new fields; V1 imports still preserve V2/V2.1 fields. Exports retain `version: 2` with `app: T-English` and `appVersion: 2.1.0`, allowing old V2 format consumers to preserve unknown additive fields. Before-V2 recovery data and unreadable payload protection remain intact.

## Desktop build
`scripts/build_desktop.py` creates `release/T-English.html`, an instruction file and deterministic `release/T-English_V2.1_PC.zip`. The HTML embeds the curriculum, vocabulary, exercises, styles and scripts. It takes an explicit embedded-data initialization path and never fetches dependencies or registers a service worker. The same application runs on web and file origins.

A standalone file origin is separate from the website. Transfer is explicit JSON export/import; no automatic access to the user's old website storage is attempted. File-origin persistence varies by browser and path, so the user is told to keep the file at a fixed location and export backups. No claim is made that the file itself is rewritten with user progress.

## Validation and limitations
CI runs original/V2/V2.1 data and logic checks, desktop/mobile browser scenarios, full topic-test scoring, report safety/export, goals, corrupt-state recovery and legacy backup roundtrips. It opens the standalone HTML via file:// with networking disabled, checks zero HTTP requests and tests progress after reload plus backup transfers in both directions. The live URL is tested after deployment. Screenshots and the tested desktop ZIP are retained in the build artifact.

Browser tests are Chromium at desktop/mobile viewports. Windows/macOS-specific shell integration, physical phone behavior and availability/quality of system speech voices require user acceptance on actual devices. No AI, cloud account, microphone capture or paid service is added.
